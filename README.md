# Resume Unification

Build three resume versions from shared LaTeX components and specialty-specific
experience and project descriptions. Python uses only the standard library.

## Components

```text
components/
  __init__.py
  headlineBanner.txt
  education.txt
  skillsAndInterests.txt
  preamble_start.txt
  preamble_end.txt
  experienceStart.txt
  experienceEnd.txt
  projectStart.txt
  projectEnd.txt
  PerformanceEngineering/
  GenericSWE/
  TradingResearch/
```

The nine text files at the root are shared by all three resumes. Edit these to
change the header, education, skills, layout, or section wrappers everywhere.
Each specialty folder holds its own experience and project descriptions. To
specialize a shared component, put a file with the same name in that specialty
folder; it takes precedence over the root copy for that resume.

`VARIANTS` in `main.py` controls which components appear and their order:

| Variant | Content folder | Generated source |
| --- | --- | --- |
| `performance_engineering` | `components/PerformanceEngineering/` | `generatedResumes/performance_engineering_resume.tex` |
| `swe` | `components/GenericSWE/` | `generatedResumes/swe_resume.tex` |
| `trading_research` | `components/TradingResearch/` | `generatedResumes/trading_research_resume.tex` |

The generic SWE selection and wording are unchanged from the previous Desktop
version. Performance engineering and trading research use the newer Downloads
components and selections. Trading research replaces the former Quant output.
Performance engineering also includes a customized Face Bell Smart Doorbell
component focused on pipeline latency and frame processing; its proposed
implementation details are marked P13 and P14 in `REVIEW_NOTES.md`.
Generic SWE retains Bright Bridge and CPU Architecture as optional components;
trading research retains Quackston and CPU Architecture as optional components.

The imported specialty components retain their original review comments.
`REVIEW_NOTES.md` contains the corresponding performance engineering and trading
research notes.

## Generate

From the project directory, build all three LaTeX files and matching PDFs:

```sh
python3 main.py
```

Build one version, or repeat `--variant` to select several:

```sh
python3 main.py --variant swe
python3 main.py --variant performance_engineering --variant trading_research
```

Paths are resolved relative to `main.py`, so it also works when called from a
different directory.

To generate only the LaTeX sources, skip PDF compilation:

```sh
python3 main.py --no-pdf
```

PDF generation uses the `pdflatex` LaTeX compiler. It first checks `PATH`, then
the project-local TinyTeX installation in `.tools/TinyTeX/bin/`. TinyTeX and the
packages used by `components/preamble_start.txt` are installed locally on this
machine, so no system PATH changes are needed. The compiler directory is
Git-ignored; a fresh clone needs its own TeX installation.

Each resume is compiled twice and checked for a single page and layout overflow.
The PDFs are saved beside their `.tex` files in `generatedResumes/`; compilation
logs and auxiliary files are kept under `generatedResumes/.latex-build/`.
`--pdf` remains accepted for compatibility, but PDFs are now generated by default.
All selected `.tex` files are written before compilation starts, so they remain
available if compilation reports an error.

The existing Git ignore rules still exclude `components/` and
`generatedResumes/`; their contents are local files rather than Git-tracked
resume history.
